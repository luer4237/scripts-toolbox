# Scripts Toolbox 内容规范

用于本仓库中脚本、功能目录和说明文档的新增、修改与整理。先查看目标目录及相邻 README，保持现有命名和语气；不要把本规范扩展成对无关代码或配置的要求。

## 目录与归类

- 当前按运行平台放置：支持多个平台的内容放在 `scripts/cross-platform/`，Windows 专用内容放在 `scripts/windows/`。新增内容先依据这两个现有目录判断归类。
- 会被 Shell 初始化流程加载的内容放在对应平台的 `auto/`；必须由用户明确执行的内容放在 `manual/`。
- 每个具体功能建立独立目录，一个目录只负责一个相关用途。
- 每个功能目录至少包含脚本文件和同目录的 `README.md`。新增功能时同步补齐文档；修改命令、参数、依赖或行为时同步更新文档。
- 目录级 README 只介绍该目录的职责。项目根目录 `README.md` 除了维护目录约定和分类规则，还要维护每个工具的简介与路径索引；不要在根 README 中堆积具体工具的完整使用说明。

## 自动加载与副作用

- `auto/` 中被 `source` 的脚本必须以注册函数、命令或环境配置为主，加载时不应立即执行重启、删除、写入系统配置等副作用操作。
- 需要 Docker、系统代理、进程权限、管理员权限或其他外部状态的操作，应通过明确命令触发，并在 README 中说明影响范围。
- `manual/` 脚本可以执行启动、停止、删除、重启和系统管理操作，但必须在文档中标明风险及不可逆行为。
- 不要把手动管理脚本放入自动加载目录，也不要让直接 `source` 自动脚本隐式修改系统状态。

## README 写法

### 根目录 README

- 根目录 README 应提供工具索引，让读者能快速知道每个工具是什么以及在哪里找到它。
- 每个工具至少记录：工具名称、简短功能简介、相对路径；必要时补充支持平台或自动/手动执行类型。
- 工具路径使用从仓库根目录开始的相对路径，并链接到工具目录或入口 README，例如 `[Docker Proxy](scripts/cross-platform/auto/docker-proxy/README.md)`。
- 新增、删除、移动或重命名工具时同步更新根 README 的索引，避免出现失效路径或遗漏工具。
- 根 README 的工具简介保持简短；依赖、参数、完整命令和注意事项放在对应功能目录的 README 中。

功能目录 README 使用清晰的中文 Markdown，通常按以下顺序组织：

1. `# 功能名称`
2. `## 功能`：说明解决的问题、作用对象和重要行为。
3. `## 文件`：仅在目录内有多个需要区分的文件，或文件职责不直观时添加。
4. `## 平台与依赖`：列出操作系统、Shell/运行时、命令行工具、版本要求和权限要求。
5. `## 使用方式`：给出可复制的命令；命令前说明运行位置、是否需要 `source`、管理员权限或准备步骤；参数、默认值和常见模式要与脚本实际行为一致。
6. `## 注意事项`：说明副作用、权限、安全风险、平台差异、持久化位置、清理方式和已知限制。

文档要求：

- 使用相对链接引用同目录文件，例如 `[script.sh](script.sh)`；不要写只在作者机器上成立的绝对路径。
- 命令示例必须可执行且与脚本入口、参数名称、默认配置一致；不要记录尚未实现的选项。
- 用代码块展示命令、配置和目录结构；用列表表达依赖、支持的平台和多个选项。
- 对会修改 Docker、网络、进程调度、系统权限或系统配置的行为明确提示影响，不弱化风险，也不建议无条件关闭安全机制。
- 描述平台差异时写清跨平台脚本与 Windows 脚本的限制，不要把 Windows 专属命令写成跨平台行为。

## 新增或修改时的检查

完成后至少检查：

- 路径是否符合平台与 `auto/`/`manual/` 分类，目录名和文件名是否简洁、稳定、易识别。
- 根目录 README 是否已登记每个工具的简介和路径，路径是否仍然有效。
- 功能目录是否有对应 README，README 是否覆盖功能、依赖、使用方式和注意事项。
- README 中的命令、参数、环境变量、默认值和权限要求是否能从脚本实现中得到验证。
- 自动加载脚本是否避免加载即产生副作用，手动脚本的破坏性操作是否有说明。
- 只运行与改动相关的检查；不要为了文档变更修改无关文件。
